# The Atlas is orientation: the model's word, never Verified

On a large codebase, choosing what to practise needs a map that says what things are *for*: "this folder is the database layer", "`retryWithBackoff` is where failed jobs come back". Fiu builds that map, the Atlas, from two parts. The skeleton (folders, files, symbols with their line ranges, logic scores, practice state) is computed locally from the code and is correct by construction. The descriptions are written by a model, and nothing can measure whether they are true, so the Atlas breaks the rule every Workout follows ([ADR 0007](./0007-answers-are-measured-never-asserted.md)).

We accept that because the Atlas is never a Workout. It is labelled as written by a model, it never feeds the Verified gate, and its only power is to suggest a target: a wrong description at worst points the human at a less interesting function, and the Workout made from that target is measured like any other. What *is* checked mechanically is every name the Atlas shows: each symbol it describes exists in the skeleton, so search results and `file#symbol` targets always resolve. We rejected Atlas-based quizzes ("which folder handles payments?") for the reason ADR 0007 gives, and we rejected a parser-based symbol index (tree-sitter) because it would add native dependencies to a pure-Node package for names that only have to be good enough to put after `#`.
