# Workout code always runs sandboxed, with no network

Every execution of Workout code (verification and the runner alike) happens inside an OS sandbox (`@anthropic-ai/sandbox-runtime`: bubblewrap on Linux, Seatbelt on macOS) with network fully denied, writes confined to the Workout directory and a per-user toolchain cache, known secret locations and the repository itself unreadable, and a scrubbed environment. If no working sandbox is available, Fiu refuses to run Workout code unless the user passes `--no-sandbox` on that invocation; this is never persisted.

The threat is prompt injection: users drill code they didn't write, and text in that code can steer the LLM into emitting code that verification then executes unattended. Denying network is what makes exfiltration impractical, and it's only affordable because Workouts are standard-library-only ([ADR 0001](./0001-workouts-are-stdlib-only.md)). The two decisions reinforce each other: any future feature needing network access or real dependencies inside a Workout must revisit both. Native Windows is unsupported (WSL only) because it has no comparable lightweight sandbox.
