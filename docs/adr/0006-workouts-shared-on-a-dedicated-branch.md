# Workouts are shared on a dedicated `fiutsu/workouts` branch

Teams share Workout definitions (and Track manifests) on an orphan branch, `fiutsu/workouts`, in the repository they were derived from. `fiu share` publishes to it and `fiu fetch` reads from it; Fiutsu writes the branch with git plumbing, so the user's working tree, index, and current branch are never touched. Only definitions travel: Attempts, state, the spend ledger, and config stay on each person's machine.

Workouts contain code derived from the repository, so whoever can read them can read part of the code: sharing must reach exactly the people who can read the repository, and no one else. A branch in the same repository inherits that access control and git's transport for free, works offline, and needs no infrastructure. We rejected a folder tracked on the main branch (it breaks "zero repo pollution" and puts Workouts in every diff and pull request), a separate repository (one more thing to set up, whose access control can drift from the code's), and a hosted service (accounts, storage, and a second place code-derived content lives; a public library remains a separate, later decision). The cost: pushing a new branch can trigger CI on some setups, and Workouts referring to commits that were never pushed can't show their sources to teammates (so `fiu share` refuses uncommitted-code Workouts and warns about unpushed commits).
