# Understand-Anything's graph is read as orientation, never as Links

[Understand-Anything](https://github.com/Egonex-AI/Understand-Anything) (UA) builds a knowledge graph of a repository with a pipeline of model agents and keeps it in the repository, in `.understand-anything/knowledge-graph.json`, or in `.ua/` when that legacy directory is absent. A team that has paid for that graph has, sitting on disk, much of what Fiu's Atlas asks a model to write: a sentence on what each file and significant function is for, tags, architectural layers, and a guided tour in teaching order. When the graph is there, Fiu reads it, in the same directory order UA uses, with no flag; a setting turns it off. Fiu never runs UA, never depends on its packages, and never writes to its directory ([ADR 0005](./0005-called-by-agents-never-driving-them.md) for the same reason: Fiu reads what the user's tools have left behind and drives none of them).

What Fiu takes from the graph is the model's word, exactly as the Atlas is ([ADR 0008](./0008-the-atlas-is-orientation-never-verified.md)): labelled with its source (*written by a model (Understand-Anything), not Verified*), never input to the gate, and practising nothing. Its names pass the Atlas's own check: a UA function or class counts only when it resolves to a symbol in Fiu's skeleton, and a file only when the skeleton lists it, so every `file#symbol` it suggests resolves. A description is cut to its first sentence and to the Atlas's 200 characters. It is current when the file's blob hash today matches the file at the commit UA analysed, and stale otherwise, so the `≈` marker means the same thing for both sources. Fiu's own entry wins when it is current; a UA entry fills in where Fiu has none or a stale one. Building the Atlas follows the same rule: a file whose UA entry is current costs nothing to describe, because Fiu doesn't describe it; its folder is still Fiu's to write. That is the point of reading the graph, since the tokens were already spent once. The graph is read in place, never copied into `.fiu/atlas.json`: the two sources stay told apart, a UA re-run reaches Fiu at once, and `fiu share --atlas` never passes UA's text off as Fiu's. A team shares UA's graph by committing it, as UA already supports.

Before an answer, UA's text goes into "Around this code" only through the same filter as any Atlas entry ([ADR 0009](./0009-context-is-orientation-links-are-computed-facts.md)). Its author never saw the Workout, which is the condition that ADR sets. UA's per-file lessons (`code-lessons.json`) explain the target itself, so they wait for the Debrief. So do UA's business flows (`domain-graph.json`): after an Attempt, the Debrief says which step of which flow the target is, and what comes before and after, labelled as UA's. A step's line range counts only while its file is as UA read it. A flow can also be a Track (`fiu explore --flow`): its files, in the order the flow reaches them, are the candidates, and the plan keeps that order. The flow only chooses and orders files; every step is still a Workout, Verified like any other.

UA's edges are not Links. Its `imports` edges come from a deterministic scanner, but `calls`, `depends_on`, `related` and the rest are inferred by a model, and ADR 0009 keeps Links true by construction because a wrong one misleads. Fiu goes on computing its own Links; UA's inferred edges may appear only in the Debrief, labelled as UA's, beside the computed ones and never merged with them.

UA's format is not a contract: its `version` field is a constant, and its directory and field names have changed before. So the reader takes only the fields Fiu uses, treats each as optional, parses every node, layer and tour step on its own and skips the ones it can't read, and never lets the graph cost a command or a Workout: an unreadable graph is reported in one dim line and ignored. A format change Fiu can't see in the shape shows in the result, as names that stop resolving; when few of the graph's code nodes match the skeleton, Fiu says the format may have changed rather than getting quietly worse. Everything that knows UA's shapes lives in one module.

We rejected importing UA's entries into the Atlas (two authors in one file, shared under Fiu's name, and a second copy to keep fresh), treating UA's `calls` edges as Links (a model's inference presented as a computed fact), turning UA's tour into a Track (one repository-wide tour of 5 to 15 multi-file steps is too broad; a business flow, a few ordered steps each in one file, is the unit that fits a Track), and an explicit flag to enable the reader (the graph's presence is the user's intent, and its source is always shown).
