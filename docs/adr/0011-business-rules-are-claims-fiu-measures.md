# Business rules are claims Fiu measures, whoever wrote them

A business rule ("orders over €50 ship free", "at most 3 suggestions a day") is a claim about what the system does. Teams keep such claims in their heads, in specs, and in tools that write them down for them, and nothing checks them against the code: a rule can be wrong the day it is written, or turn wrong when the code changes. Fiu already measures behaviour without trusting anyone's word ([ADR 0007](./0007-answers-are-measured-never-asserted.md)), so a rule becomes the topic of a Prediction: a Scenario where the rule makes a difference, whose true answer is what the code does, measured, whatever the rule says. The model that wrote the Prediction reports whether the measured behaviour agrees with the rule; that comparison is its reading, shown as such, of a Verified result.

Rules come from three sources, and the rest of Fiu treats them alike. The team's own `.fiu-rules.md`, committed with the code: one rule per Markdown list item, a heading as its domain, and an optional `→ path#symbol` pinning where it is enforced. Understand-Anything's domain graph, when there is one ([ADR 0010](./0010-understand-anything-is-read-as-orientation-never-as-links.md)). And a sentence the human types, when it matches no known rule and says enough to be one (4 words or more). A rule shows its source wherever it is shown; the team's file wins over a model-written rule with the same text; turning Understand-Anything off removes only its rules.

Where a rule is enforced is the weak part: a pinned rule needs no guess, a rule naming a function or a constant leads to the code using it, and otherwise Fiu searches the rule's words (among its domain's files, when it has one) and keeps only places sharing several of them. A guess is always confirmed by the human before anything is spent. The rule is never shown before answering, since it often states the answer. A check holds while the function it measured is unchanged; once that changes, the rule is due for a re-check.

We rejected keeping rules as part of the Understand-Anything integration (the measurement never needed it, and most repositories will never have its graph), storing the team's rules in `.fiu/` (Fiu keeps that out of git, and rules are the team's to share and review), extracting rules from documents with a model call of Fiu's own (Understand-Anything already does this, and a team can write the rules that matter in one line each), and treating a rule's agreement as Verified (only the behaviour is measured; whether a sentence describes it is a reading).
