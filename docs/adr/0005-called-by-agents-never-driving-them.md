# Kintsugi can be called by your coding agent, but never drives an agent

Kintsugi generates Workouts in two ways: by calling an LLM API with the user's own API key, or by being *called* by the user's coding agent (Claude Code, Cursor, …) through Kintsugi's MCP server, while the user is working with that agent. In the second case the agent writes the candidate Workout in its own session and submits it; Kintsugi verifies it in the sandbox and saves it. Kintsugi never logs in to an AI subscription, never holds subscription credentials, and never starts an agent itself (no `claude -p`, no `codex exec` with a ChatGPT login, no Agent SDK with a claude.ai login).

Users wanted Workouts without API bills, on the flat-rate subscriptions they already pay for. Driving those subscriptions from a third-party tool runs against providers' terms (Anthropic doesn't allow third-party products to offer claude.ai login or subscription rate limits without approval; OpenAI recommends API keys for automation and advises against ChatGPT-login automation in open-source repositories), so we rejected it. Being a tool that the user's agent calls during the user's own session is the standard way these agents are extended, and keeps Kintsugi out of the credentials business entirely. The cost: background generation (the v2 commit watcher) still needs an API key, because nothing can wake the user's agent, and Kintsugi can't measure what agent-generated Workouts cost.
